# CLAUDE.md

## Project Overview

Model Council is an automated multi-model verification system for research reports. It takes a primary research report (typically generated by Gemini) and dispatches it to independent verification models in parallel, then synthesizes their feedback into a final validated report with consensus/divergence analysis.

Two workflow versions exist:
- **V1**: Full council — always dispatches all 3 models (~45k tokens)
- **V2**: Risk-adaptive — classifies report risk, optionally runs Perplexity web-search pre-check, and dispatches only the models needed (~30k tokens avg, -33% cost)

## Tech Stack

- **Language**: Python 3.11+ (stdlib only — no third-party packages)
- **HTTP client**: `urllib.request` (no requests/httpx)
- **External service**: OpenClaw Gateway (`POST /tools/invoke`) for session management and web search
- **Package management**: pip with `requirements.txt` (currently empty since all deps are stdlib)

## Running the Scripts

All scripts are in `src/scripts/` and use relative imports from `common.py`. Run from the `src/scripts/` directory:

```bash
cd src/scripts

# V1 workflow
python3 dispatch.py /path/to/report.md
python3 collect.py <run-ids-or-json>
python3 synthesize.py /path/to/council-runs/<timestamp>/

# V2 workflow (recommended)
python3 dispatch_v2.py /path/to/report.md [--max-queries 5] [--full]

# Standalone tools
python3 risk_router.py /path/to/report.md [--pretty]
python3 perplexity_check.py /path/to/report.md [--max-queries 10]
```

## Environment Configuration

Scripts need access to the OpenClaw Gateway. Configuration is resolved in this order:

1. Environment variables: `OPENCLAW_GATEWAY_URL`, `OPENCLAW_GATEWAY_TOKEN`
2. Config file: `~/.openclaw/openclaw.json` (keys: `gateway.port`, `gateway.auth.token`)
3. Default URL: `http://127.0.0.1:18789`

If `sessions_spawn` is blocked, enable it in the Gateway config:
```json
{ "gateway": { "tools": { "allow": ["sessions_spawn"] } } }
```

## Architecture & Data Flow

```
Primary Report
  → Risk Assessment (risk_router.py: low/medium/high)
  → Perplexity Pre-check (perplexity_check.py, for low/medium risk)
  → Dispatch to 1–3 Models in parallel (dispatch_v2.py)
      - codex: openai-codex/gpt-5.3-codex (technical)
      - sonnet: google-antigravity/gemini-3-pro-high (business)
      - strategic: google-antigravity/gemini-3-pro-high (strategic)
  → Collect outputs (collect.py: polls subagent status)
  → Synthesize (synthesize.py: consensus ≥ 2/3 agreement, divergence = unique claims)
  → Final Report written to references/<topic>-council-final.md
```

Risk routing strategy:
- **High risk** → full council (3 models, ~45k tokens, no Perplexity)
- **Medium risk** → Perplexity + codex only (~30k tokens)
- **Low risk** → Perplexity only (~15k tokens)
- Escalation gate: if critical claims are contradicted, adds sonnet model

## Key Conventions

### Code Style
- `from __future__ import annotations` in every module
- Type hints on all function signatures (uses `typing.Literal`, `typing.Any`)
- Custom exception: `OpenClawToolError(RuntimeError)` for API failures
- Scripts use `argparse` with `main()` entry points and `if __name__ == "__main__"` guards
- Chinese + English mixed in keyword lists and documentation (bilingual project)

### Output Artifacts
- Dispatch manifests: `references/council-runs/<timestamp>/dispatch.json`
- Collection manifests: `references/council-runs/<timestamp>/manifest.json`
- Per-model outputs: `references/council-runs/<timestamp>/{role}.md`
- Session transcripts: `references/council-runs/<timestamp>/{role}.history.json`
- Final reports: `references/<topic>-council-final.md`

### Template Pattern
Templates in `src/templates/` use `[PLACEHOLDER]` markers (e.g., `[PRIMARY_REPORT]`, `[TOPIC]`) that are replaced via `str.replace()` at runtime.

## Testing

No tests are currently implemented. The `tests/` directory contains only `__init__.py`. A comprehensive test plan exists in `docs/model-council-test-plan.md` covering:
- Unit tests for risk_router, perplexity_check, dispatch logic
- Integration tests (component workflows)
- E2E tests (full pipeline)
- 5 test datasets defined (D1–D5) across risk levels

There is no pytest configuration, no linter configuration, and no CI/CD pipeline.

## Important Notes for AI Assistants

- All source code lives under `src/`. The `scripts/` subdirectory has flat imports (`from common import ...`) so scripts must be run from `src/scripts/`.
- The project uses only Python stdlib — do not add third-party dependencies without discussion.
- The `.gitignore` excludes `*.json` files globally. Manifest/state JSON files in `references/` and `src/state/` are not tracked.
- Perplexity quota is tracked in `src/state/perplexity_quota.json` (167 queries/day max).
- The `references/` and `data/` directories are gitignored runtime output directories.
- When modifying templates, keep the `[PLACEHOLDER]` convention — the codebase uses simple string replacement, not a template engine.
